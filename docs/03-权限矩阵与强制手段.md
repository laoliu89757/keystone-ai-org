# 权限矩阵与三层强制

版本 v1.0｜2026-10-21｜读者：项目负责人、SRE、幕僚长

> 原则：**提示词只是第一道软约束，真正生效的是平台。** 三道防线，任何一道都不能省：
> **① Paseo 工具裁剪（减少误操作）→ ② 本地钩子（拦截危险命令与越界路径）→ ③ GitHub 平台（分支保护 / CODEOWNERS / Environment 审批，不可绕过）。**

**四条不容商量的红线**

1. 任何 Agent 都没有生产数据库直连权限；生产迁移只能由流水线在**人**批准后执行。
2. 任何 Agent 都不接触密钥值；CI 用环境密钥注入，生产密钥只在 production environment 可见。
3. 改 CI / 门禁 / CODEOWNERS / 评测基线，只有 SRE 与评测官能提 PR，且必须 CODEOWNERS 所有者（人）批准。
4. 每个岗位一个独立机器人账号（GitHub App 或机器账号），不给管理员权限；**只有独立评审官**的账号能写 `agent-review` 检查，开发账号不能自己给自己放行。

## 2 第一层：Paseo 工具裁剪

在 `~/.paseo/config.json` 的 `agents.providers` 里，用 `extends` 造三个变体（本仓库 `.paseo/config.patch.json` 已写好，执行 `python .paseo/apply_profiles.py` 合并）：

```jsonc
{
  "agents": { "providers": {
    "claude-lead":   { "extends": "claude", "label": "Claude · 编排层（CEO）" },
    "claude-worker": { "extends": "claude", "label": "Claude · 执行层",
      "paseoTools": { "disabledTools": [
        "create_agent", "create_schedule", "create_heartbeat",
        "kill_agent", "archive_agent", "archive_workspace",
        "respond_to_permission", "update_agent", "set_agent_mode", "create_terminal"
      ]}},
    "pi-worker":     { "extends": "pi", "label": "Pi · 执行层",
      "paseoTools": { "disabledTools": [ /* 同上 */ ] } }
  }}
}
```

改完必须 `paseo reload`，并**新开 Agent 或重载**才生效（运行中的会话保留启动时的工具目录）。

| 被禁工具 | 防住什么 |
| --- | --- |
| `create_agent` / `create_schedule` / `create_heartbeat` | 执行者自己招人、自己开定时任务（绕过 CEO） |
| `respond_to_permission` | 给自己/给别人批权限请求 |
| `update_agent` / `set_agent_mode` | 自己把模型换成更贵的、把模式换成全权限 |
| `kill_agent` / `archive_*` | 弄丢别人的会话与工作区 |
| `create_terminal` | 在别人目录里开终端乱搞 |

⚠️ 官方明示：这只是"呈现给 Agent 的工具目录"，**对有 shell 的 Agent 不是安全边界**。所以还要第二、三层。

## 3 第二层：本地钩子与权限配置

`.claude/settings.json`（Claude 系 Agent）与 pi 的等价配置：

```json
{
  "permissions": {
    "allow": [
      "Bash(git status)", "Bash(git diff:*)", "Bash(git add:*)", "Bash(git commit:*)",
      "Bash(pytest:*)", "Bash(ruff:*)", "Bash(mypy:*)",
      "Bash(npm run lint)", "Bash(npm test:*)", "Bash(vendor/bin/phpunit:*)"
    ],
    "deny": [
      "Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)",
      "Edit(./.github/**)", "Edit(./.claude/**)", "Edit(./CODEOWNERS)",
      "Edit(./evals/baseline/**)", "Edit(./AGENTS.md)",
      "Bash(git push --force:*)", "Bash(git push -f:*)", "Bash(git reset --hard:*)",
      "Bash(rm -rf:*)", "Bash(curl:*)", "Bash(ssh:*)", "Bash(kubectl:*)", "Bash(mysql:*)"
    ]
  },
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "bash scripts/hooks/guard_bash.sh" }] },
      { "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "bash scripts/hooks/guard_paths.sh" }] }
    ]
  }
}
```

两个钩子脚本见 `scripts/hooks/guard_bash.sh`、`scripts/hooks/guard_paths.sh`（`AGENT_ROLE` 环境变量由启动方注入，值 = 岗位代号）。JSON 取值优先用 `jq`，没有 `jq` 时自动回退到 `scripts/hooks/_tool_field.py`（Windows Git Bash 常见无 jq，务必确认回退可用，否则钩子会静默放行）。

- `guard_bash.sh`：拦 `drop table|truncate`、`git push ... main|master`、`--no-verify`、`chmod -R 777`，退出码 2 = 阻断并把 stderr 反馈给 Agent。
- `guard_paths.sh`：先拦全局受保护路径，再按 `AGENT_ROLE` 做目录白名单（`backend/`、`learning-service/`、`app/`、`migrations/`、`tests/`、`evals/`、`docs/`…）。

> 本地配置可能被 Agent 改掉，所以 `.claude/` 与 `.pi/` 本身列入 CODEOWNERS 受保护路径，且第三层不可绕过。

## 4 第三层：GitHub 平台（唯一真正的边界）

**main 分支保护**：禁止直推与 force push；必需检查 `backend / learning-service / frontend / contract / migrations / secrets / pr-size / e2e / agent-review`（路径触发 `eval-gate`）；必需 1 个审批；受保护路径由 CODEOWNERS 审批；新提交撤销旧审批；要求对话已解决、分支最新；管理员同样受限。

**Environments**

| 环境 | 审批人 | 分支限制 | 密钥 |
| --- | --- | --- | --- |
| eval | 无 | 任意 PR 分支 | 只放有额度上限的评测密钥 |
| staging | 无 | 仅 main | 测试密钥 |
| production | **项目负责人（必需）** | 仅 main | 生产密钥，只有此环境可见，管理员不可绕过 |

**CODEOWNERS**：见仓库根 `CODEOWNERS`（`.github/`、`infra/`、`CODEOWNERS`、`evals/baseline/`、支付与权益目录、掌握判定阈值、`docs/adr/`、`.claude/`、`.paseo/`、`AGENTS.md` → 项目负责人）。

**Agent 账号**：只授予"写非保护分支、开 PR、读检查结果"；不给 admin；不给 environment 密钥访问权；`agent-review` 检查写入权限**只给独立评审官账号**。

## 5 人工审核点（Agent 不可自批）

**必要权限审核（8 项）**

| 审核点 | 触发 | 收到的材料 | 强制机制 |
| --- | --- | --- | --- |
| 生产发布 | 每次 | 发布说明、staging 验收、回滚方案 | production environment 审批人 |
| 生产数据库迁移 | 含迁移的发布 | 迁移/回滚脚本、副本演练记录、备份确认 | 同上 |
| 密钥/账号/权限变更 | 变更时 | 变更清单与理由 | 只在平台人工操作 |
| 付费服务与预算 | 新增/超预算 | 成本估算与用量 | 同上 |
| 学生数据外发/换模型供应商 | 变更时 | 数据流向、合规核对 | 评测门禁 + CODEOWNERS |
| 删除数据 | 任何删除 | 范围与备份 | 工具权限禁止，人工执行 |
| 合规结论 | 备案/隐私/平台政策 | 合规清单与待确认项 | 人工确认才算完成 |
| 门禁与流水线变更 | 改 CI/CODEOWNERS/基线 | 差异与理由 | CODEOWNERS 必须人批 |

**标准审核（固定清单）**：ADR、里程碑验收报告、教学内容抽检、评测对比报告、高危安全项。

**不需要人处理**：单 PR 评审与合并（过门禁自动）、测试环境部署、依赖小版本升级、文档与变更日志、常规缺陷修复。

## 6 三层如何互相兜底

| 攻击/失误场景 | Paseo 层 | 钩子层 | 平台层 |
| --- | --- | --- | --- |
| 开发想让评审官"顺便"改代码 | 无（评审无 create_agent） | 只读白名单拦写 | 评审账号无 push 权限 |
| 开发改 `.github/workflows` 放宽门禁 | 无 | `guard_paths.sh` 拦 | CODEOWNERS 要人批 |
| 开发给自己加权限 | `respond_to_permission` 已禁 | — | 机器人账号无 admin |
| 开发 force push main | — | `guard_bash.sh` 拦 | 分支保护拒绝 |
| 开发删测试让 CI 变绿 | — | — | 评审 + 覆盖率阈值（受保护）阻断 |
| 评测集被悄悄放宽 | — | `evals/baseline/**` deny | CODEOWNERS 要人批 |
| 机器人账号批生产发布 | — | — | 不在审批人名单 |

**每次改动任一层后，必须重跑 `docs/04-落地清单与演练.md` 的 10 项演练。**
