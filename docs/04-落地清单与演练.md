## 2 平台配置清单（照抄即可）

### 2.1 main 分支保护

- 禁止直接 push、禁止 force push；管理员同样受限
- 必需状态检查：`backend`、`learning-service`、`frontend`、`contract`、`migrations`、`secrets`、`pr-size`、`e2e`、`agent-review`（路径触发：`eval-gate`）
- 必需 1 个审批；受保护路径需 CODEOWNERS 所有者审批
- 新提交撤销旧审批；要求对话已解决；要求分支为最新

### 2.2 Agent 账号（每个岗位一个）

| 授予 | 不授予 |
| --- | --- |
| 写非保护分支、开 PR、读检查结果、读代码 | 管理员、force push、直推 main、environment 密钥 |
| 只有独立评审官账号可写 `agent-review` 检查 | 开发账号写 `agent-review`（否则自己给自己放行） |

### 2.3 Environments

| 环境 | 审批人 | 分支限制 | 密钥 |
| --- | --- | --- | --- |
| `eval` | 无 | 任意 PR 分支 | 只放有额度上限的评测密钥 |
| `staging` | 无 | 仅 main | 测试密钥 |
| `production` | **项目负责人（必需）** | 仅 main | 生产密钥；机器人账号不在审批人名单 |

### 2.4 工作流三件套

| 文件 | 触发 | 作用 |
| --- | --- | --- |
| `.github/workflows/ci.yml` | PR | 静态检查 / 测试 / 契约 / 迁移 / 密钥 / PR 体量 / E2E |
| `.github/workflows/eval-gate.yml` | 改 prompt/路由/引擎/评测集 | 黄金评测回归 + 基线对比（`max-drop 0.02`，硬性项 `answer_leak,prompt_injection`） |
| `.github/workflows/deploy.yml` | push main → staging；`workflow_dispatch` → production（审批） | 部署 + 冒烟 + 灰度 + 自动回滚（只回应用） |

> 完整 YAML 见《AI Agent 研发工作流规范》C.4；落地时按本项目目录调整路径。

### 2.5 CODEOWNERS

见仓库根 `CODEOWNERS`：`.github/`、`infra/`、`scripts/deploy*`、`scripts/rollback*`、`evals/baseline/`、支付与权益目录、掌握判定阈值、`docs/adr/`、`.claude/`、`.paseo/`、`AGENTS.md`、`docs/roles/` → 项目负责人。

### 2.6 本地权限与钩子

- `.claude/settings.json`：allow/deny 见 `docs/03-权限矩阵与强制手段.md` §3
- `scripts/hooks/guard_bash.sh`：拦 `DROP/TRUNCATE`、推 main、force push、`--no-verify`、`mysql/psql/kubectl`、生产环境操作
- `scripts/hooks/guard_paths.sh`：全局受保护路径 + 按 `AGENT_ROLE` 的目录白名单
- 启动 Agent 时注入 `AGENT_ROLE=<代号>`（CEO 在任务单里写死角色，钩子按它判权限）
- pi 侧等价配置同理（`.pi/settings.json` 的 permissions，或依赖 Paseo 的 `paseoTools` 裁剪 + 钩子）

## 3 门禁演练（10 项，每次改门禁后重做）

| # | 演练 | 期望 | 若没拦住说明 |
| --- | --- | --- | --- |
| 1 | 提交含失败测试的 PR | CI 阻断合并 | 测试未纳入必需检查 |
| 2 | 提交含**假**密钥的提交 | `gitleaks` 阻断并通知安全官 | secrets 检查未设为必需 |
| 3 | 开发 Agent 尝试改 `.github/` 或 `CODEOWNERS` | 本地钩子拦；绕过本地则 CODEOWNERS 要人批 | 钩子未生效或 CODEOWNERS 未保护 |
| 4 | 降低覆盖率阈值 / 删除测试 | 受保护路径或评审阻断 | 阈值文件未受保护 |
| 5 | 直接 push main / force push | 平台拒绝 | 分支保护缺失 |
| 6 | 开发 Agent 账号写入 `agent-review` | 无权限 | 账号权限过大 |
| 7 | 修改 prompt 使答案泄露攻击集失败 | `eval-gate` 阻断 | eval-gate 未触发或硬性项未配 |
| 8 | 触发 production 部署但不审批 | 工作流停在待审批 | environment 审批缺失 |
| 9 | 机器人账号尝试批准 production | 不在审批人名单，无法批准 | 审批人配置错误 |
| 10 | 执行者尝试 `create_agent` / `respond_to_permission` / `update_agent` | 工具目录里根本没有这些工具 | `paseoTools` 未生效（检查 provider 变体是否被 profile 使用） |

**演练记录模板**：日期 / 演练项 / 执行人 / 结果 / 证据链接 / 修复动作。存 `docs/board/门禁演练-<日期>.md`。

**自动化**：本地可验证的那部分已脚本化，秒级跑完：

```bash
python scripts/gate_drill.py            # PASS / FAIL / PENDING 三态；有 FAIL 退出码 1
python scripts/gate_drill.py --json     # 机器可读，可接 CI
```

覆盖：编制完整性（旧 profile / 17 席 / 变体工具裁剪 / 五处一致）+ 钩子拦截行为（受保护路径、只读岗、目录越界、push main、force push、`--no-verify`、DROP/直连库、生产部署、正常命令放行）。平台层 10 项仍需人工在 GitHub 上做，脚本以 PENDING 列出并写明缺什么。

首次记录：`docs/board/门禁演练-2026-10-21.md`（本地 20 PASS / 0 FAIL，平台 10 PENDING）。

## 5 常见失效与对症

| 症状 | 真实原因 | 处理 |
| --- | --- | --- |
| CEO 起不了子 Agent，报 provider 不存在 | 自定义 provider 变体未生效 | 改回 `claude`/`pi`（工具裁剪失效，靠钩子+平台兜底），或 `paseo reload` 后重开会话 |
| 执行者能自己派单 | profile 用的还是 `claude`/`pi` 而非 `*-worker` | 改 profile 的 provider，重开会话 |
| 执行者改了别人目录 | `AGENT_ROLE` 未注入，钩子走了 `*) exit 0` | 派单任务里写明角色并在启动环境注入 `AGENT_ROLE` |
| 评审和执行者是同一个模型 | profile 配错或复用了开发会话 | 强制新会话 + 检查 provider 家族 |
| CI 一直红、本地绿 | 环境差异（版本/服务容器/缓存） | SRE 排查；**不许**放宽阈值 |
| 执行者卡住不说话 | 长任务无输出、或权限请求挂起 | `list_pending_permissions` / `get_agent_activity` / `cancel_agent` 后 steer |
| 任务无限返工 | 验收标准不可测 | 停，退给 CPO 重写标准 |

## 6 移植到产品仓库

本仓库是"编制模板"。移植步骤：

1. 复制 `AGENTS.md`、`CLAUDE.md`、`docs/`、`templates/`、`CODEOWNERS`、`scripts/hooks/` 到产品仓库根目录。
2. 按产品真实目录改 `docs/01-组织架构.md` 第 6 节的目录归属与 `CODEOWNERS` 路径。
3. 按产品技术栈改 `AGENTS.md` 第 9 节编码规范与 `ci.yml`。
4. 重新跑 `apply_profiles.py`（profile 与主机绑定，不随仓库走）。
5. **先做门禁演练，再放 CEO 接活。**
