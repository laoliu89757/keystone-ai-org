## 0. 数值粒度裁决（先读）

任务单 T-001-B 第 3 条字面写"掌握度 int 0–100"，第 6 条同时要求"79.9 / 80.0 / 80.1 三档边界可被测试构造，且同为整数**或明确小数位**"。两条合并读：AC-11 强制存在 0.1 粒度的分数（79.9、80.1 本身即小数），整数无法表达。

**裁决**：全数值体系采用**明确小数位 = 1 位**（任务单第 6 条的第二个选项）：

- 掌握度 `mastery`：float，恒等于 `round_half_up(x, 1)` 的结果，范围 [0.0, 100.0]；
- 理由条目贡献值 `contribution`：float，同为 1 位小数粒度。

依据：任务单第 6 条是计分公式的专门条款，比第 3 条的泛称"int"更具体；且 AC-11 的三档构造只有在该粒度下可实现。QA 断言方式：`mastery == round_half_up(mastery, 1)` 且 `abs(contribution*10 - round(contribution*10)) < 1e-9`。

## 1. 背景

学生完成某知识点的一组练习后，系统须给出：掌握度（0–100）、是否放行、下一步动作（promote / consolidate / review），且判定**可解释**（每条结论对应到规则名 + 贡献值）。约束：Python 3.11、纯标准库、纯函数、无副作用、确定性、顺序无关；难度权重随难度递增（具体曲线由本 ADR 钉死）。

CPO 需求 v1.0 §6 列出 6 个待架构师确认项，本 ADR 逐条消解（见 §12）。

## 2. 决策总览

采用**双项计分制**：

> **掌握度 = clamp( (加权正确率项 + 难度加成项) × 连错折减因子 , 0, 100 )，四舍五入到 1 位小数。**

- 加权正确率项（满分 70）：权重曲线 `difficulty_weights = (1, 2, 3, 5, 8)` 只作用于这一项；
- 难度加成项（满分 30，题量=10 时）：表 `difficulty_bonus = (0.0, 0.7, 1.0, 2.0, 3.0)`，**只发给答对的题**；
- 连错折减：存在长度 ≥ 3 的连错段时整体 ×0.90（**乘法而非减法**，理由见 §6 与 §11.4）；
- 全部参数集中在一个配置结构 `MasteryConfig`，无散落魔法数字。

参数总表（钉死，全部为默认值，可被 config 覆盖但产品默认以此为准）：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `pass_threshold` | `80.0` | 放行阈值，**含端点**（≥ 80.0 放行） |
| `min_questions` | `10` | 最低题量，不足 → `measured = False` |
| `streak_critical` | `3` | 连错临界段长 |
| `accuracy_weight` | `70.0` | 加权正确率项满分 |
| `difficulty_bonus_total` | `30.0` | 难度加成项满分（= 10 题 × 3.0，题量更大时由钳制兜底） |
| `difficulty_weights` | `(1, 2, 3, 5, 8)` | 按难度 1–5 索引（d−1），加权正确率用 |
| `difficulty_bonus` | `(0.0, 0.7, 1.0, 2.0, 3.0)` | 按难度 1–5 索引（d−1），每答对一题加分 |
| `streak_factor` | `0.10` | 连错折减系数（有段时 ×(1−0.10)） |
| `review_threshold` | `60.0` | 巩固/复习分界（< 60 → review） |
| `mastery_decimals` | `1` | 掌握度小数位 |
| `knowledge_point_id_pattern` | `^[a-z][a-z0-9_]{2,31}$` | 知识点 ID 格式 |
| `duration_seconds_max` | `7200` | 单题耗时上限（秒） |

## 3. 判定输入 Schema

### 3.1 记录字段（钉死）

每条答题记录（`AnswerRecord`）含 **5** 个字段：

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `knowledge_point_id` | `str` | 匹配 `^[a-z][a-z0-9_]{2,31}$`（3–32 字符，小写字母开头，仅小写字母/数字/下划线） | 知识点 ID，须 ∈ 已登记集合 |
| `difficulty` | `int` | 1 ≤ x ≤ 5，**且不是 bool**（`bool` 是 `int` 子类，须显式排除） | 题目难度 |
| `is_correct` | `bool` | 严格 `bool` 类型 | 是否答对 |
| `duration_seconds` | `int` 或 `float` | 有限（非 NaN/Inf）、0 ≤ x ≤ 7200、且不是 bool | 单题耗时（秒）；**只做记录，不参与计分**（见 §3.4） |
| `submitted_at` | `int` | Unix 时间戳（秒），x ≥ 0，且不是 bool | 答题提交时序——**规范排序键**（见 §3.3） |

> **为什么多出 `submitted_at`**：AC-14 要求同一集合乱序输入结果不变，而 AC-13 的连错检测需要顺序。二者同时成立的唯一解法是时序来自**数据字段**而非列表顺序。`submitted_at` 是入参数据，不违反 AC-05（引擎不自行读时钟）。

### 3.2 非法值处理（钉死，显式报错，禁止静默当 0 / 截断 / 夹取）

异常类型（全部继承 `ValueError`，fail-fast：校验按记录顺序进行，**遇到第一条非法记录立即抛出**）：

```
MasteryInputError(ValueError)                     基类
├── InvalidAnswerRecordError(MasteryInputError)   字段级非法
└── UnknownKnowledgePointError(MasteryInputError) 知识点 ID 未登记
```

错误信息格式（钉死，QA 按此断言；只含字段值，不含学生个人信息）：

```
InvalidAnswerRecordError:
  "invalid answer record [index={i}] field={field}: {reason} (got {value!r})"
  reason ∈ {"type_mismatch", "id_format", "difficulty_range",
            "duration_range", "submitted_at_range"}
  示例: "invalid answer record [index=3] field=difficulty: difficulty_range (got 6)"

UnknownKnowledgePointError:
  "unknown knowledge point [index={i}]: {id!r} not in known set (size={n})"
  示例: "unknown knowledge point [index=0]: 'kp_nope' not in known set (size=42)"
```

逐字段非法值判定表：

| 字段 | 非法情形 | reason |
| --- | --- | --- |
| `knowledge_point_id` | 非 `str`、空串、不匹配正则 | `type_mismatch` / `id_format` |
| `knowledge_point_id` | 格式合法但 ∉ 已登记集合 | → `UnknownKnowledgePointError` |
| `difficulty` | 非 `int`（含 `bool`、`float`、"3"） | `type_mismatch` |
| `difficulty` | int 但 < 1 或 > 5 | `difficulty_range` |
| `is_correct` | 非 `bool` | `type_mismatch` |
| `duration_seconds` | 非 int/float（含 `bool`）、NaN、±Inf | `type_mismatch` |
| `duration_seconds` | < 0 或 > 7200 | `duration_range` |
| `submitted_at` | 非 `int`（含 `bool`）、< 0 | `type_mismatch` / `submitted_at_range` |
| `records` 本身 | 非 `Sequence`，或元素非 `Mapping` | `type_mismatch`（index=该元素下标） |

### 3.3 规范排序（顺序无关性的显式处理）

校验通过后，以**全字段元组升序**排序作为唯一计算顺序：

```
key = (submitted_at, knowledge_point_id, difficulty, is_correct, duration_seconds)
```

`submitted_at` 是时序唯一事实来源；同时间戳的并列记录按后续字段排序，保证任何输入顺序都得到**同一个**规范序列（AC-14）。已知局限：同时间戳的记录之间真实答题先后不可辨，连错段可能与真实作答顺序不同——调用方必须传真实提交时间。

### 3.4 耗时与计分的关系

`duration_seconds` 仅作为必填字段记录与校验，**不参与掌握度计算**。理由：需求非目标 §5.8 明确不校验耗时真伪；耗时参与计分会引入"抢答博弈"且使分数构造复杂化。此为 v1.0 决策，若未来要引入速度维度，须新 ADR。

## 4. 判定输出 Schema

### 4.1 成功结果（`MasteryResult`，钉死）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `mastery` | `float \| None` | 非 None 时 ∈ [0.0, 100.0]，恒为 1 位小数 | 掌握度；**数据不足时为 `None`** |
| `measured` | `bool` | — | `False` = 题量 < 10（数据不足），`True` = 正常测量 |
| `passed` | `bool` | — | 放行与否；`passed == (measured and mastery >= 80.0)` |
| `action` | `Literal["promote","consolidate","review"]` | 三值枚举 | 下一步动作 |
| `reasons` | `tuple[Reason, ...]` | 非空，顺序钉死（见 §4.3） | 理由列表 |

`Reason`（每条理由，钉死）：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `rule` | `str` | ∈ §4.3 规则名枚举 |
| `contribution` | `float` | 1 位小数粒度（可为 0.0、负数） |
| `detail` | `str` | 非空，含关键数值的可读说明 |

### 4.2 "数据不足"形态（消解 CPO §6.4）

题量 `n < min_questions(10)`（含 0 题、1 题）时：

```
MasteryResult(
    mastery = None,            # 可被程序区分于任何已测量分数（AC-07/AC-08）
    measured = False,
    passed = False,            # 数据不足绝不放行
    action = "review",         # 数据不足 → 补练习，归入 review
    reasons = (
        Reason("insufficient_data", 0.0, f"题量 {n} < 最低要求 10，无法测量掌握度"),
        Reason("action_rule", 0.0, "action = review：数据不足，先补足题量"),
    ),
)
```

### 4.3 理由规则名枚举与顺序（钉死）

正常测量时 `reasons` 依序含以下条目（QA 可按名字与顺序断言）：

| 顺序 | `rule` | `contribution` | `detail` 模板 |
| --- | --- | --- | --- |
| 1 | `weighted_accuracy` | `round_half_up(70×A, 1)` | 加权正确率 A（答对权重 C / 总权重 S） |
| 2 | `difficulty_bonus` | `round_half_up(Σbonus, 1)` | 答对题的难度加成合计与分布 |
| 3 | `consecutive_miss` | `−round_half_up(折减量, 1)`；无段时 `0.0` | 最长连错段长 L、段数 k、是否触发临界 3 |
| 4 | `clamping` | `round_half_up(clamp 后 − clamp 前, 1)` | **仅当钳制实际生效**（越界）时出现 |
| 5 | `threshold_rule` | `0.0` | `passed` 的判定依据（mastery 与阈值 80.0 的比较） |
| 6 | `action_rule` | `0.0` | `action` 的判定依据（走了哪条分支） |

不变式：列表非空；`rule` ∈ 枚举；`contribution` 为 1 位小数；`detail` 非空（AC-01/AC-03）。

### 4.4 错误契约（消解 CPO §6.2）

**选择抛异常**（而非错误状态结构）。理由：非法输入是调用方程序缺陷（Schema 违约或脏数据），不是业务状态；异常让错误在调用点立即暴露，无法被当作正常分数继续流转（AC-15/AC-16 的"绝不静默"）；数据不足（题量少）是**合法业务状态**，走 `MasteryResult` 正常返回，不是异常。两种形态边界钉死如上。

## 5. 计分公式与难度权重曲线

### 5.1 公式（钉死，消解 CPO §6.1/§6.6）

记规范排序后的记录为 r₁…rₙ（n ≥ 10），`[cᵢ]` 为答对指示（1/0），`w(d)`、`b(d)` 分别查 `difficulty_weights` / `difficulty_bonus` 表（索引 d−1）：

```
① 加权正确率项   acc  = 70 × ( Σ w(dᵢ)·[cᵢ] ) / ( Σ w(dᵢ) )        ∈ [0, 70]
② 难度加成项     bon  = Σ [cᵢ] × b(dᵢ)                              ∈ [0, 30]（n=10 时）
③ 连错折减       has_streak = 规范序中存在连续错误段，段长 ≥ 3
                 m1   = (acc + bon) × (1 − 0.10·[has_streak])       即 ×1.00 或 ×0.90
④ 边界钳制       m2   = min(100, max(0, m1))
⑤ 舍入           mastery = round_half_up(m2, 1)                     ∈ [0.0, 100.0]
⑥ 放行           passed  = measured ∧ (mastery ≥ 80.0)              含 80.0 端点
```

顺序与任务单第 6 条一致：**加权正确率 → 连错惩罚 → 边界钳制 → 舍入**。舍入规则钉死为**四舍五入（half-up）**，不用 Python 内置 `round`（银行家舍入）——实现方须自行实现 half-up（如 `math.floor(x*10 + 0.5)/10`，x ≥ 0 时安全）。放行判定基于**舍入后的 mastery**，保证学生看到的分数与放行结论永不矛盾。

### 5.2 难度权重曲线（钉死）

| 难度 d | 权重 `w(d)`（正确率项） | 加成 `b(d)`（答对加成） |
| --- | --- | --- |
| 1 | 1 | 0.0 |
| 2 | 2 | 0.7 |
| 3 | 3 | 1.0 |
| 4 | 5 | 2.0 |
| 5 | 8 | 3.0 |

两表职责不同，**不可合并**：`w` 是正确率内部的区分度（比率制，分子分母同乘时消去）；`b` 是绝对加分（使难度差异**不被归一化消掉**——这是 AC-12 严格大于的结构性保证）。两表均严格递增，满足 INTENT-001 §3"难度权重随难度递增"。

### 5.3 数学证明一：高难全对 > 低难全对（AC-12）

**命题**：n ≥ 10，两组均全对（无连错段，因子 = 1.00），组 P 全部难度 5，组 Q 全部难度 1，则 mastery(P) > mastery(Q)。

**证**：全对 ⇒ A = 1，acc = 70。

- 组 Q：bon = 10 × b(1) = 0 ⇒ m1 = 70 ⇒ m2 = 70 ⇒ mastery = 70.0。
- 组 P：bon = 10 × b(5) = 30 ⇒ m1 = 100 ⇒ m2 = min(100, 100) = 100 ⇒ mastery = 100.0。

100.0 > 70.0 ∎。

**一般形式**：对同题量、全对的两组，若组 X 每题难度 ≤ 组 Y 对应题难度且至少一题严格更高，则 Σb(X) < Σb(Y)（b 表严格递增，最小严格增量 0.7），m1(X) < m1(Y)。**饱和例外**（诚实声明）：当先到 100 的一方被钳制（如全难度 4、n ≥ 15：70 + 2×15 = 100），更高难度不再增加分数，此时严格性失效。**QA 构造 AC-12 必须用 n = 10**（该题量下仅难度 5 全对恰达 100，无两方同时饱和）。∎

### 5.4 数学证明二：同条件部分错 < 全对（AC-09）且全错 = 0.0（AC-10）

**命题 A**：同题量、同难度分布，全对与错 k ≥ 1 题相比，后者严格更低。
**证**：错题使 A 的分子减 w(d) > 0 而分母不变 ⇒ A 严格下降 ⇒ acc 严格下降；同时该题失去加成 b(d) ≥ 0 ⇒ bon 不升。故 base 严格下降；两组连错状态相同时折减因子相同 ⇒ mastery 严格下降。∎

**命题 B**：全错时 mastery = 0.0，且低于"同分布至少对 1 题"的任何情形。
**证**：全错 ⇒ acc = 0, bon = 0 ⇒ m1 = 0×factor = 0 ⇒ clamp(0) = 0 ⇒ mastery = 0.0。对 ≥ 1 题时 base = 70A + bon > 0（A ≥ w(d)/Σw > 0）；乘以 (1 − 0.10) ∈ {0.90, 1.00} **保正**（正数乘正数仍正），clamp 只削上界 100 ⇒ m2 > 0。舍入可能把 < 0.05 的值归为 0.0——触发条件为 `63/(8n−7) < 0.05` 即 **n ≥ 159**（最劣分布：1 题难度 1 答、其余难度 5 连错）；实践题量（n ≤ 50）下恒有 mastery > 0.0。**QA 构造 AC-10 用 n = 10**。∎

## 6. 连错惩罚与恢复规则（钉死，含任务单第 5 条要求的"连错 ≥3 后转对"规则）

1. **检测**：规范序（§3.3）中，极长连续错误段（maximal run of `is_correct = False`），段长 L ≥ `streak_critical`(3) 记为有效段。
2. **扣分**：存在 ≥ 1 个有效段 ⇒ 整体乘 `(1 − streak_factor) = 0.90`。**flat 制**：段数与段长不加重折减。
3. **恢复**：段因答对而终止（"连错 ≥3 后转对"）时，该段封账、不再累计；**答对无额外回补加分**——答对的价值已由正确率项与难度加成项体现，回补会造成双重计分。
4. **信号不吞掉**（AC-13a）：`consecutive_miss` 条目**恒出现**于理由列表——触发时 contribution = −折减量、detail 写明最长段长与段数；未触发时 contribution = 0.0、detail 写明"最长连错 L < 3，不折减"。
5. **对动作的影响**（消解 CPO §6.5）：未放行且触发连错 ⇒ `action = "review"`（强制，无论 mastery 是否 ≥ 60）——连错 3 说明存在系统性误解，仅"巩固"不足，须回看讲解。已放行时连错不影响放行（分数已含折减，门槛判定一致）。

## 7. 动作判定规则（钉死）

```
if not measured:            action = "review"      # 数据不足，补题
elif passed:                action = "promote"     # mastery ≥ 80.0
elif has_streak:            action = "review"      # 连错信号强制复习（§6.5）
elif mastery < 60.0:        action = "review"      # 未达巩固线
else:                       action = "consolidate" # 60.0 ≤ mastery < 80.0 且无连错
```

不变式（AC-02）：`passed ⇔ action == "promote"`；`not passed ⇒ action ∈ {"consolidate", "review"}`。

## 8. 纯函数接口签名（算法工程师照此实现，QA 照此写测试；消解 CPO §6.3）

```python
# learning-service/ 下实现；仅标准库；无 I/O、无时钟、无随机、无全局可变状态

@dataclass(frozen=True)
class MasteryConfig:
    pass_threshold: float = 80.0
    min_questions: int = 10
    streak_critical: int = 3
    accuracy_weight: float = 70.0
    difficulty_weights: tuple[int, ...] = (1, 2, 3, 5, 8)        # 索引 d−1
    difficulty_bonus: tuple[float, ...] = (0.0, 0.7, 1.0, 2.0, 3.0)  # 索引 d−1
    streak_factor: float = 0.10
    review_threshold: float = 60.0
    mastery_decimals: int = 1
    knowledge_point_id_pattern: str = r"^[a-z][a-z0-9_]{2,31}$"
    duration_seconds_max: float = 7200.0

DEFAULT_CONFIG = MasteryConfig()

@dataclass(frozen=True)
class Reason:
    rule: str                 # §4.3 枚举
    contribution: float       # 1 位小数粒度
    detail: str               # 非空

@dataclass(frozen=True)
class MasteryResult:
    mastery: float | None     # None 当 measured=False
    measured: bool
    passed: bool
    action: str               # "promote" | "consolidate" | "review"
    reasons: tuple[Reason, ...]

def validate_records(
    records: Sequence[Mapping[str, object]],
    known_knowledge_points: Collection[str],
) -> None:
    """校验 §3.2 全部规则；非法即抛 MasteryInputError 子类（fail-fast）。"""

def judge_mastery(
    records: Sequence[Mapping[str, object]],
    known_knowledge_points: Collection[str],
    *,
    config: MasteryConfig = DEFAULT_CONFIG,
) -> MasteryResult: ...
```

- `known_knowledge_points` **必填**（消解 CPO §6.3）：合法知识点集合由调用方从配置/存储读出后以入参传入（推荐 `frozenset[str]`）；**空集合法**但会使所有记录抛 `UnknownKnowledgePointError`——配置缺失应尽早暴露，不做静默跳过。
- `records` 为空序列时走 §4.2 数据不足分支（不报错）。
- 判定前先 `validate_records`（引擎内部调用，调用方无须二次校验）。
- 建议实现放在 `learning-service/`（具体模块路径由算法工程师定，接口签名以本节为准）。

## 10. 备选方案（≥2 个被否方案及否决理由）

| # | 备选方案 | 否决理由 |
| --- | --- | --- |
| 1 | **纯加权正确率制**：`mastery = 100 × Σw·[c]/Σw` | 全对时 A ≡ 1 饱和，难度 5 全对 = 难度 1 全对 = 100.0，**违反 AC-12 严格大于**；权重在比率制中被约分消掉，形同虚设 |
| 2 | **每题固定计分制**：`mastery = Σ score(dᵢ)·[cᵢ]`（无归一化） | 分数随题量线性膨胀，不同题量结果不可比；题量大时大面积钳到 100，"对 1 题 vs 对 2 题"在饱和区无区分；产品语义（百分制掌握度）被破坏 |
| 3 | **IRT / ELO 等统计模型** | 需要 存量数据拟合与历史状态，违反"纯函数 + 无存储 + 标准库"约束；能力 θ 不可分解为"规则名 + 贡献值"，违反可解释性要求（AC-03）；INTENT-001 红线要求规则引擎而非模型 |
| 4 | **阶梯连错罚**（每段 −5、段长每超 1 题再 −2） | 减法罚可把"对 1 题"压穿 0 与"全错"相等（已验算：全难1×10 对 1 题错序为 3+6 两段时 raw = 7 − 10 < 0），**违反 AC-10 严格小于**；乘法折减天然保正，故弃减法 |
| 5 | **掌握度整数化（int）** | 无法表达 AC-11 的 79.9 / 80.1，违反任务单第 6 条；见 §0 裁决 |
| 6 | **非法值静默夹取**（难度 6 → 5、未知 ID 当 0 分跳过） | 违反 AC-15/AC-16"绝不静默"；脏数据静默流入学生界面是 INTENT-001 §2 可信性要求的反面 |

## 11. 代价

1. **双表认知成本**：`difficulty_weights` 与 `difficulty_bonus` 两个难度结构并存，实现/评审需理解"比率项 vs 绝对项"分工（§5.2 已写明，测试锚定两表）。
2. **低难全对不放行**：难度 1 全对 = 70.0、难度 2 全对 = 77.0，均 < 80 不放行。产品语义：低难度全对不足以证明掌握。**产品与运营需知情**（学生视角"全对却没过"须有解释文案）。
3. **连错折减 flat 10%**：连错 10 题与连错 3 题同罚，段长信息只进 detail 不进分数——v1.0 有意简化，保 AC-10/AC-13 可测；加重罚需新 ADR。
4. **half-up 需自实现**：Python `round` 是银行家舍入，实现方必须自写（§5.1 已给安全式）；漏写会在 .x5 边界产生 ±0.1 偏差。
5. **`submitted_at` 成为必填**：调用方必须提供真实提交时序，接入成本 +1 字段；不传则无法判定连错（Schema 直接拒绝）。
6. **理论归零边界**：n ≥ 159 的极端分布下"对 1 题"可能被舍入为 0.0（§5.4 命题 B），与全错同分。实践题量内不触发，登记为已知局限。

## 13. 回滚方式

1. **参数级回滚**（最常用）：全部数值集中于 `MasteryConfig` 单点，恢复旧默认值 = 改一个 frozen dataclass，无散落魔法数字需要清查。
2. **公式级回滚**：本 ADR 的决策由新 ADR 显式取代（标记 superseded），实现按"先扩展后收缩"——新旧两套 config 并行一个过渡期，调用方灰度切换后删除旧路径。
3. **Schema 级回滚**：`submitted_at` 为本 ADR 新增的必填字段；回滚时引擎退回上一版本的同时，调用方停止传该字段（字段是新增而非改写既有字段，对旧引擎是多余键——旧引擎若严格拒绝未知键，则按 §1 约定调用方与引擎**同版本原子回退**）。
4. **回滚单位**：本 ADR 全部决策落于一个纯函数模块 + 一个配置结构，git revert 单提交即可，无数据迁移、无存量数据风险（引擎无存储）。
