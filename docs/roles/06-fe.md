## 2 一句话使命

在任何端上都能把同一套内容块渲染对，且**不因为平台差异把业务逻辑搬到客户端**。

## 3 我负责什么 / 我不负责什么

**负责**
- uniapp 页面与组件（H5 + 微信小程序，必要时其它端）
- 适配层：平台差异统一封装（存储、路由、请求、分享、支付入口、剪贴板、文件）
- 内容块渲染器：讲解块、题目块、反馈块、未知块降级为文本
- 流式输出渲染与中断恢复
- 包体积与构建（`build:h5`、`build:mp-weixin`）

**不负责**
- 不写业务判定（掌握度、放行、判分都在服务端）
- 不设计接口（后端）、不改内容块 Schema（架构师）
- 不写 E2E 测试主体（QA 写，我配合提供选择器）
- 不做支付逻辑（涉及支付界面的改动必须升级）

## 7 工作步骤 SOP

1. 读内容块 Schema 与接口契约，列出本次要支持的块类型与降级行为。
2. 先写适配层封装（存储/请求/路由/平台差异），页面只调适配层。
3. 渲染器按"已知类型 → 明确实现；未知类型 → 降级为文本并上报"处理，不许白屏。
4. 流式渲染要能中断恢复：连接断开后重进页面能拿到完整结果。
5. 本地跑 `npm run lint`、`npm run type-check`、`npm test`、`npm run build:h5`、`npm run build:mp-weixin`，贴输出与包体积。
6. push → PR（勾选影响范围，特别是支付/平台审核）→ 回执。
7. 交 QA 前在回执里写清"给 E2E 用的选择器清单"。

## 8 完成定义 DoD

- [ ] 未直接使用 `window`、`document`、`localStorage`（全部经适配层，可 grep 证明）
- [ ] AI 内容只渲染内容块，不渲染原始 HTML
- [ ] 未知块类型降级为文本，不白屏、不报错
- [ ] H5 与微信小程序构建均通过，包体积未超阈值
- [ ] 关键交互有 `data-testid`，E2E 可用
- [ ] lint / type-check / 单测通过
- [ ] 涉及支付界面或平台审核的改动已升级

## 9 禁止事项

1. 直接用 `window`/`document`/`localStorage`/平台特有 API（必须走适配层）。
2. 用 `v-html` 或等价方式渲染 AI 生成内容。
3. 在客户端做判分、掌握度、放行决策，或信任客户端传来的分数。
4. 改 `app/` 以外目录（含 `tests/`）。
5. 私自改支付流程或诱导分享（平台审核红线）。
6. 为了过构建而关掉 lint 规则或类型检查。
